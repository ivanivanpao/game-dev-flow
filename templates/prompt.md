把【】內的東西換成你的內容。之後每一輪的修改改用 TASK.md；這份會一直當成設計文件，每一輪都交給開發者與程式審查者。）

## 一、場景（你要做出什麼）
【一兩段話：玩家看到什麼、能做什麼。例如：一個第三人稱的草地場景，玩家能用斧頭砍樹、用鎬挖石頭。】
視覺風格：【例如：低多邊形、柔和打光、霧氣遠景。】

## 二、限制（不能違反）
- 技術：【例如：Three.js（three/webgpu）、不用其他遊戲引擎。】
- 建置後的成品是一個可直接開啟的 HTML 檔；但原始碼要照下面「程式架構」分成多個模組，不要全寫在同一個檔案裡。
- 全部程序生成：不載入任何外部圖片、模型、音效或 CDN 套件，貼圖和音效都用程式即時算出。
- 所有隨機都用可指定種子的亂數；同一個種子必須產生同一個世界。
- 暴露 `window.__game`：至少包含 ready、設定鏡頭、觸發動作、凍結動畫、世界座標轉螢幕座標。

## 三、效能目標
- 在【我的電腦：顯示卡型號】上，平均幀時間 ≤ 【16.7】 ms（60 fps），p95 ≤ 【25】 ms。
- 量測方式：自動飛行路徑跑 【10】 秒，用 rAF 間隔統計。

## 四、怎麼自己驗證
- 建置：`npm run build` 必須成功。
- 開頁面後 console 不得有錯誤。
- 照 shots.json 的鏡頭截圖，再由「只看圖的審查者」回報視覺缺陷。
- 效能超標或有視覺缺陷，就回頭修，直到通過。

## 五、程式架構（每一輪都要遵守）
目標是遊戲做大之後還好改：每個檔案只負責一件事，模組之間的依賴方向固定。
檔案長度不設上限；但一個檔案或類別開始負責不相干的事，就該拆。

```
src/
├── main.js          只做組裝：建立各模組並接起來。不直接 import three 等套件、不寫遊戲邏輯
├── models.js        唯一 import 已發布模型（models/_released/）的地方；其他檔案從這裡拿模型
├── core/            底層：繪圖器（WebGPURenderer 初始化）、主迴圈、輸入、種子亂數、事件匯流排
├── entities/        遊戲物件（玩家、樹、石頭…）：類別＋組合，繼承最多一層
├── systems/         遊戲規則（砍樹、背包、鏡頭…）：一個系統一個類別；系統之間透過事件或公開方法溝通，不直接改別的系統的內部狀態
└── debug/
    └── game-api.js  window.__game 測試介面集中在這裡
```

下面這些由 `checks/arch-check.mjs` 自動檢查，違反就不通過：
- core/ 不能 import entities/、systems/、debug/
- entities/ 不能 import systems/、debug/
- systems/ 不能 import debug/
- 不能有循環引用（A import B，B 又 import A）
- 只有 src/models.js 能 import models/_released/
- main.js 不能直接 import 套件
- 全域變數只能有 window.__game 和 window.__renderBackend
